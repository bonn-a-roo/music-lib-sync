# Session Resume — music-lib-sync

Short entrypoint for resuming development. Details belong in the [spec](spec.md), [runbook](runbook.md), [backlog](backlog.md), and [area guidance](agents/README.md).

## State — 2026-10-05

- Modern media-library UI direction recorded in [ADR-0001](adr/adr-0001-media-library-ui.md). Approved minimal dark/cyan styling is implemented. The browser supports scoped missing/selected-track sync, retry, Sync all across ready accessible collections, and confirmed whole-library Repair Library through a single-active queue with cancellation and post-repair rescan. Scoped sync itself does not implicitly repair or move nested files. Local playback is integrated with a Qt/FFmpeg codec fallback; final Computer Use and end-to-end desktop validation remain pending.
- Approved styling: minimal dark surfaces, restrained cyan borders/highlights, flat controls and reduced decoration; not super-high contrast. Built-in local playback remains required in the first complete redesigned release.
- Immutable collection/track snapshots, independent metadata/coverage/operation fields, read-only local index and operation-scoped WorkerEvent payload contracts are implemented. `SpotifyLibrary.sync_collection` and the browser worker emit/consume stable-ID events; legacy batch sync still does not. Sync / repair remains accessible from the browser.
- Preview exercised in Chromium: collection navigation, filters/search, queue/cancel promotion, restricted/synced states, global activity, Details and player selection. The preview remains design evidence, not production verification; local playback code is now integrated, but audible output and live provider sync are unverified.
- Offline fixture browser smoke proved local presence, duplicate rows/unique counts, search/missing filters, playlist navigation, elsewhere-file exclusion and Restricted display. Added focused scoped-sync, Sync all, repair-queue, playback-codec and file-safety tests using temporary data. Full offline suite: 238 passed. Live Spotify/provider behavior and audible output are unverified.
- Computer Use passes (2026-10-05; harnesses over generated temporary audio and a fake library/downloader; `test/` and user audio untouched). Verified in the real window: playback of a Qt-native format and of FLAC/M4A/Opus/Ogg via the FFmpeg fallback, pause/resume, next/previous, rapid switching (last request wins, one temp WAV, no orphan FFmpeg), seek by click, Repair Library accepted/declined while a FLAC and while a native MP3 were playing (player stopped first, real move of the MP3 to `_rejected` succeeded, row became Quarantined after the rescan), close while playing (no temp dir or FFmpeg left), a damaged file (short actionable error, row stays Downloaded with a playback error), Sync all across Saved/Mix with a restricted collection excluded and reported, Cancel jobs mid-run (both collections Cancelled, no extra downloads, one rescan), playback continuing across collection navigation with a per-collection queue, keyboard Enter/Space on the table, and a narrow layout. The user confirmed audible output works. Fixed during these passes: click-to-seek, theme for sliders and scrollbars, header alignment, focus rectangles, sidebar alignment and width stability, short playback errors, Enter/Space playback, clipped Status column and sidebar status line in narrow windows. Not covered: high-DPI scaling (window scale cannot be changed through Computer Use), close during FFmpeg decode through the GUI (decode finishes faster than a GUI round trip; covered by `test_quiesce_waits_for_ffmpeg_and_qt_to_release_playback_files`), real Spotify/yt-dlp downloads, Tab-order audit, and screen-reader checks.
